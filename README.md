# WinFix — обслуживание Windows одной программой

Один исполняемый файл `winfix.exe` (без зависимостей, пишется на Go): интерактивное меню с подсказками
к каждому пункту **и** командная строка для скриптов. Диагностика и починка Windows 10/11: мусор, драйверы,
целостность системы, память, сеть.

Принцип везде одинаковый: **сначала диагностика и показ результата, потом действие с подтверждением.**

## Быстрый старт

1. Скопируйте `winfix.exe` на любой компьютер с Windows 10/11 (ничего ставить не нужно — нужен только
   встроенный Windows PowerShell) и запустите двойным щелчком.
2. Программа сама запросит права администратора (UAC) — без них часть пунктов недоступна.
3. Выберите **«Проверка здоровья компьютера»** — она покажет, что именно требует внимания,
   и подскажет, какая утилита что исправляет.

Хотите, чтобы WinFix был «установлен»? Пункт меню **«Установить WinFix на этот компьютер»** (или `winfix install`)
копирует программу в `%LOCALAPPDATA%\Programs\WinFix`, добавляет команду `winfix` в PATH и создаёт ярлык
на рабочем столе и в меню «Пуск» с запуском от администратора. Права администратора для установки не нужны.
Удалить: `winfix uninstall` — убирает программу, ярлыки и запись в PATH.

## Утилиты

В меню у каждого пункта есть подсказка — что делает и зачем. Те же утилиты доступны из командной строки.

| Утилита | Для чего | Документация |
|---|---|---|
| `health` | общий отчёт о состоянии ПК + подсказка, чем что чинить | [docs/windows/health.md](docs/windows/health.md) |
| `junk` | временные файлы, кэши, дампы, логи, корзина | [docs/windows/junk.md](docs/windows/junk.md) |
| `drivers` | проблемные/старые драйверы, Windows Update, резервная копия | [docs/windows/drivers.md](docs/windows/drivers.md) |
| `repair` | SFC, DISM, CHKDSK, WMI, Windows Update, Store, время, Defender | [docs/windows/repair.md](docs/windows/repair.md) |
| `memory` | память, утечки, модули RAM, тест памяти, лимит WSL2 | [docs/windows/memory.md](docs/windows/memory.md) |
| `network` | диагностика сети, DNS, сбросы, TCP-настройки | [docs/windows/network.md](docs/windows/network.md) |

Рекомендуемая плановая профилактика раз в месяц: `health` → `junk` → `drivers report` → при необходимости `repair`.

## Командная строка

```
winfix                          интерактивное меню (рекомендуется)
winfix <утилита>                меню одной утилиты, например: winfix network
winfix <утилита> <команда> ...  выполнить команду без меню, например: winfix network diag
winfix help [утилита]           справка и список команд
winfix install | uninstall      установить на компьютер / удалить
winfix version                  версия
```

Примеры:

```
winfix health run --no-save     отчёт без сохранения файла
winfix junk scan                сколько мусора можно удалить (ничего не удаляется)
winfix junk clean --yes         очистить рекомендуемое без вопросов (для планировщика задач)
winfix repair full              диагностика + SFC + DISM + CHKDSK
winfix drivers report           проверка драйверов без изменений
```

Прежние имена утилит (`netfix`, `memcheck`, `sysrepair`, `drivercheck`, `junkclean`, `healthcheck`) работают как синонимы:
`winfix netfix diag`. Если команде нужны права администратора, а их нет, программа перезапустится с запросом UAC
и оставит окно открытым до нажатия Enter.

Переменная окружения `WINFIX_NO_ELEVATE=1` отключает автоматический запрос UAC (для тестов и автоматизации).

## Где лежат данные

Всё в `%LOCALAPPDATA%\WinFix`:

| Папка | Содержимое |
|---|---|
| `logs` | журнал каждого запуска `winfix-<дата>.log` (цвета удалены; приложите при обращении за помощью) |
| `reports` | отчёты «Проверки здоровья» — сравнивайте до и после изменений |
| `backups` | резервные копии драйверов |

Формат журнала — по строке на событие: `ЧЧ:ММ:СС УРОВЕНЬ текст` (`HEAD`, `STEP`, `OK`, `WARN`, `FAIL`, `INFO`, `OUT` — вывод
системных программ, `MENU`/`INPUT` — ваши выборы), без цветов.

## Вид консоли

**Меню** — полноэкранное, как в соседнем `vpnsplit` (bubbletea): `↑↓` или `j/k` — выбор, `Enter` — запуск,
цифры — быстрый переход к пункту, `q`/`Esc` — назад или выход. Под списком всегда видна подсказка выбранного пункта
(что делает, нужны ли права администратора, какая команда у него в CLI). Выбранная команда выполняется в обычном
окне терминала (с вводом, подтверждениями и индикатором), по Enter вы возвращаетесь в меню на то же место.
Перед каждой командой экран очищается, так что результаты разных утилит не наслаиваются. В классической консоли окно само увеличивается до 110×42; в Windows Terminal размер окна программа менять не может, поэтому в невысоком окне меню переходит в компактный вид (без пояснений в шапке), чтобы все пункты были видны.
При выводе в файл/конвейер или с `WINFIX_CLASSIC=1` показывается простое меню с вводом номера.

В современном терминале (Windows Terminal, VS Code) — рамка-баннер, значки ✔ ⚠ ✖, анимированный индикатор с секундомером
во время долгих запросов, цветные полосы заполнения (память, размеры мусора) и время выполнения каждой команды.
В классической консоли и при выводе в файл/конвейер — простые ASCII-метки без цветов и анимации.
Управление: `NO_COLOR=1` — без цветов, `WINFIX_ASCII=1` — без Unicode, `FORCE_COLOR=1` — цвета и Unicode даже в конвейере.

В меню есть пункты «Открыть папку отчётов» и «Открыть папку журналов».

## Сборка на GitHub

Workflow `.github/workflows/build.yml` собирает один статический `winfix.exe` (без CGO и внешних зависимостей). Запускается только при создании тега `v*`: `go vet`, сборка, проверка запуска, затем **Release** с `winfix.exe` и `winfix.exe.sha256`
(копия также лежит в **Actions → запуск → Artifacts**):


```
git tag v1.0.0
git push origin v1.0.0
```

Версия (`winfix version`) берётся из тега.

## Локальная сборка

Нужен [Go](https://go.dev/dl/) 1.24+.

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1            # соберёт bin\winfix.exe
powershell -ExecutionPolicy Bypass -File build.ps1 -Install   # соберёт и установит
```

Или вручную: `go build -ldflags "-s -w" -o bin\winfix.exe .\cmd\winfix`.

## Структура и поддержка других ОС

```
cmd/winfix                    точка входа (несколько строк)
internal/core                 ядро, не зависящее от ОС: меню, разбор командной строки, справка, интерфейс модуля
internal/ui                   консольный интерфейс: цвета, меню с подсказками, таблицы, журнал
internal/platform             выбор модуля по ОС (platform_windows.go / platform_other.go)
internal/platform/windows     модуль Windows: утилиты, установка, всё, что зависит от системы
  ├─ win                      низкоуровневое: консоль, UAC, PowerShell, кодировки вывода, память
  └─ healthcheck, junkclean, drivercheck, sysrepair, memcheck, netfix   по пакету на утилиту
docs/windows                  документация утилит
```

Ядро знает об ОС только через интерфейс `core.Module` (список утилит, проверка и запрос прав, открытие папки;
необязательно — `core.Installer` для установки). Чтобы добавить Linux или macOS: создать
`internal/platform/linux` с типом, реализующим `core.Module`, набрать для него утилиты (`core.Tool` с командами),
и подключить в `internal/platform` файлом `platform_linux.go` (`//go:build linux`). Меню, справка, подсказки
и командная строка заработают без изменений. Пока на не-Windows система собирается заглушкой, которая честно
сообщает, что ОС не поддерживается.

Как устроена утилита: функция `Tool()` возвращает `core.Tool` — название, подсказку и список `core.Command`
(имя в CLI, название пункта меню, подсказка, нужны ли права администратора, функция запуска).
Из этого описания строятся и меню, и справка, и подкоманды.

## Что WinFix намеренно НЕ делает

- Не «ускоряет» систему твиками реестра и не чистит реестр — это не даёт выигрыша и может навредить.
- Не отключает службы Windows «для оптимизации».
- Не «очищает оперативную память» — это эффект плацебо.
- Не обновляет BIOS/EC и драйверы чипсета автоматически — это нужно делать вручную с сайта производителя.

## Требования и ограничения

- Windows 10 или 11 (x64), Windows PowerShell 5.1 (встроен в систему).
- Сообщения программы на русском языке. Разбор вывода системных утилит (SFC, DISM, chkdsk) учитывает
  русскую и английскую версии Windows; на других языках итоговые сообщения SFC могут показываться без пояснений.
